# Промпт: внедрение документации в существующий код

## Вход

- путь к целевому модулю/файлу в `src/`;
- существующие артефакты `design/`, если есть;
- тесты и контекст сборки, доступные без изменения кода.

## Правила

Не изменяй код. Не создавай `confirmed` без явного подтверждения человека. Не угадывай бизнес-смысл по именам переменных. Тесты могут быть источником наблюдаемого поведения, но не автоматически источником продуктового намерения.

## Шаги

1. Инвентаризируй файлы, точки входа, публичные интерфейсы, типы, зависимости и тесты.
2. Предложи черновой глоссарий в `design/floor1/glossary.yaml`; неочевидные определения помечай `unresolved`.
3. Предложи `US-NNN` в `design/floor1/stories/` только для наблюдаемого внешнего поведения; внутреннюю функцию не превращай автоматически в пользовательскую историю.
4. Предложи `REQ-NNN` в `design/floor2/requirements/` для подтверждаемого контракта.
5. Если есть формализуемое условие — предложи `CON-NNN` в `design/floor2/constraints/` с сигнатурой, предикатом и способом проверки.
6. Добавь в `design/trace/coverage.yaml` границу внедрения. Непокрытые части фиксируй как `not_adopted`/`legacy` по правилам проекта.
7. Все новые записи имеют `status: draft`.
8. В конце выведи список вопросов человеку. После подтверждения отдельным проходом переведи только согласованные записи в `confirmed`.
