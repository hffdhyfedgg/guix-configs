# Инструкция агенту проекта

## 1. Точка входа

Перед любой существенной работой прочитай:

1. `AGENTS.md`;
2. `design_docs/00-principles.md`;
3. `design_docs/09-naming.md`;
4. `design_docs/10-workflows.md` и соответствующий рабочий маршрут;
5. правило конкретного артефакта;
6. связанные рабочие файлы и `design/trace/`.

`design_docs/` — мета-уровень. В обычной работе он считается неизменяемым. Если меняется сам процесс, используй Трек B и `design_docs/prompts/p-evolve-process.md`; не редактируй правила молча.

## 2. Структура файлов

```text
design_docs/    # мета-правила, шаблоны, промпты, проверки; обычно неизменяем
  00-...11-*.md
  templates/
  examples/
  prompts/
  scripts/
design/         # документация конкретного проекта
  human/
  floor1/
  floor2/
  trace/
src/             # код текущего уровня
subs/             # подпроекты
  <name>/
    design/
    src/
    subs/
```

Правки в обычной работе вносятся только в `design/`, `src/` и `subs/`. Исключение — согласованное изменение самой обвязки по Треку B.

## 3. Владелец кода и симлинки

Физический файл или каталог в `src/` принадлежит тому уровню, который его редактирует. Вышестоящий уровень может получать симлинк вместо копии.

- В `subs/<name>/src/` находятся реальные файлы подпроекта.
- В `src/` родителя для делегированного модуля допускается симлинк на `subs/<name>/src/` или конкретный файл.
- Агент не создаёт копии вместо симлинков.
- Перед созданием симлинка проверь, что выбранная структура поддерживается инструментами сборки и Git данного проекта.

## 4. Общие правила

- Не превращай предположение модели в подтверждённый факт.
- Не выдумывай решения человека, критерии приёмки, технические возможности или результаты тестов.
- Отсутствующие сведения помечай как `unresolved`, `open_question`, `draft` или блокировку по правилам соответствующего артефакта.
- Подтверждение человеком относится к смыслу формулировки; `verified/passed` относится к технической проверке.
- При изменении смысла обновляй прямые связи покрытия и причинный след.
- Не выполняй декомпозицию только потому, что объект можно разбить: сначала выбери маршрут и базис.

## 5. Завершение работы

В конце сообщи:

- изменённые пути;
- смысл каждого существенного изменения;
- выполненные проверки и их фактический результат;
- открытые вопросы/блокировки;
- следующий рекомендуемый шаг.
