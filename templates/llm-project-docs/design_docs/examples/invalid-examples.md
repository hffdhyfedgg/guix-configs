# Антипримеры и способы исправления

## 1. Неопределённое выдано за неопределяемое

Плохо: `primitive: true` у термина «настройка», потому что никто ещё не решил, что это.

Почему: отсутствие определения скрыто под видом базового понятия.

Исправление: оставить `primitive: false`, записать вопрос в `unresolved`, уточнить критерии или осознанно утвердить границу формализации.

## 2. Подтверждение принятo за техническую проверку

Плохо: после ответа «да, вы правильно поняли» выставить тестовый статус `passed`.

Исправление: обновить статус подтверждения интерпретации; техническую проверку оставить `not_run` до фактического выполнения.

## 3. Диаграмма без семантики

Плохо: нарисовать коробку «настроить систему» без типа входа/выхода, изменения состояния и условий ошибки.

Исправление: задать провода, контракт и эффекты либо оставить описание на текстовом уровне, если диаграмма пока не даёт точности.

## 4. Локальные тесты вместо проверки композиции

Плохо: каждый модуль прошёл unit-тесты, значит декомпозиция корректна.

Исправление: отдельно проверить контракты границ, глобальные инварианты, ошибки и порядок операций.

## 5. МНК по впечатлению

Плохо: назвать список из нескольких подозрительных требований минимальным несовместным набором, не проверив минимальность.

Исправление: записать доказательство/результат инструмента либо `minimality: unknown`.

## 6. Теоретическая гарантия из метрики

Плохо: считать, что малый treewidth гарантирует малый конфликт без уточнения модели ограничений.

Исправление: использовать графовую метрику как диагностический признак и не заявлять гарантию без доказанных предпосылок.
