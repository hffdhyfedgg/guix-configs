# Промпт: оценка рассогласования документации и кода

## Вход

- `design/`;
- `src/`;
- опционально конкретный модуль, `REQ` или `CON`.

## Шаги

1. Найди все `REQ` и `CON` со `status: confirmed` в `design/floor2/`.
2. Инвентаризируй релевантные модули/файлы `src/`.
3. Для каждого `REQ` найди код-реализацию или зафиксируй её отсутствие.
4. Для каждого найденного соответствия сравни сигнатуры, предусловия, постусловия, ошибки, эффекты и ограничения.
5. Для каждого `CON` проверь наблюдаемое выполнение в коде или укажи, что проверка невозможна из доступных источников.
6. Для непокрытого кода создай предложение `LEG-NNN` с `disposition: not_adopted`, если он действительно вне границы внедрения.
7. Запиши только наблюдаемые расхождения в `design/trace/discrepancies.yaml`.

## Формат

```yaml
- id: DISC-NNN
  artifact: REQ-003
  code_location: src/module_1/parser.rs:42
  expected: "валидация входа перед парсингом"
  actual: "валидация отсутствует"
  severity: critical
  status: open
  rationale: ""
```

`severity`: `critical | major | minor`.
`status`: `open | resolved | accepted_deviation`.

Не меняй код и документацию. Не додумывай соответствие. Если оно неоднозначно — запиши `open_question` в отчёте и не выдавай его за доказанное расхождение.
