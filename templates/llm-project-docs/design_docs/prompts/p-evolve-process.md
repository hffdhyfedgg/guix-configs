# Промпт: изменить документационную обвязку проекта

Используй этот маршрут, когда меняются не требования самого продукта, а правила работы над проектом: `AGENTS.md`, `design_docs/*.md`, `design_docs/templates/`, `design_docs/prompts/`, `design_docs/scripts/validate_docs.py`, структура каталогов или правила `design/trace/`.

## Входы

Прочитай `AGENTS.md`, `design_docs/README.md`, `design_docs/00-principles.md`, `design_docs/09-naming.md`, текущий `design_docs/10-workflows.md`, связанные правила/шаблоны/промпты/валидатор, а также `CHANGELOG.md`, `STRUCTURE.md` и `AUDIT.md`. Приложи точный диалог или заметку, из которой возникло предложение.

## Порядок

1. Сформулируй изменение процесса как гипотезу: проблема, свидетельства, затронутые роли/треки работы, ожидаемый результат и риск побочных эффектов.
2. Сначала подготовь план, не редактируя файлы: какие документы/шаблоны/промпты/проверки затронуты; какие обратные ссылки и примеры могут устареть.
3. Различай изменение содержимого проекта и изменение правил обвязки. Если это изменение правил, не записывай его как продуктовый `REQ`/`CON`, если оно не выражает реальное требование к продукту. Зафиксируй причинное решение в `design/trace/nav-log.yaml`, если оно влияет на процесс, архитектуру документации или поведение агента.
4. После согласования внеси согласованный набор изменений согласованно: правило → шаблон/промпт → валидатор/тесты → README/структура → журнал изменений.
5. Сохраняй прежний смысл там, где изменения не требовались. Не объявляй новую теоретическую гарантию без обоснования.
6. Выполни `python design_docs/scripts/validate_docs.py` и все новые/затронутые проверки. Если проверку нельзя выполнить, пометь её `not_run`/`blocked` и объясни почему.
7. В отчёте перечисли диффы по файлам, обратные ссылки, совместимость старых артефактов, фактические результаты проверок и остаточные риски.

## Выход первого прохода

План изменения: проблема → подтверждающие примеры → список файлов → предлагаемый дифф по смыслу → проверки → риски миграции. Не применяй изменения до одобрения этого плана.
