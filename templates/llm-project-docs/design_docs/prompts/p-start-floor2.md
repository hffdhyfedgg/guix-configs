# Промпт: начать заполнение этажа 2

Это **первый проход**. Не создавай и не изменяй пока файлы `REQ`, `CON`, `COMM` или `STR`: сначала составь план и выяви решения, которые нужны от человека.

## Обязательные входы

1. `AGENTS.md`
2. `design/human/001-vision.md` и все остальные источники, перечисленные в `design/trace/coverage.yaml`
3. `design/floor1/glossary.yaml` и все рабочие `design/floor1/stories/US-*.yaml`
4. `design/trace/coverage.yaml` и `design/trace/nav-log.yaml`
5. `design_docs/00-principles.md`, `design_docs/01-glossary.md`, `design_docs/02-stories.md`, `design_docs/03-requirements.md`, `design_docs/04-diagrams.md`, `design_docs/07-communication.md`, `design_docs/08-verification.md`, `design_docs/09-naming.md`
6. `design_docs/templates/requirement.yaml`, `design_docs/templates/constraint.yaml`, `design_docs/templates/comm-diagram.yaml`, `design_docs/templates/string-diagram.yaml`

Если какой-то вход отсутствует, перечисли его явно. Не утверждай, что проверил файлы, к которым доступа не было.

## Выполни

1. Проверь готовность этажа 1: ссылки ролей/объектов/действий, источники историй, `unresolved`, статус, атомарность и покрытие исходного видения. Это не повод заново переписывать этаж 1; перечисли только блокирующие проблемы.
2. Составь матрицу для каждой истории `US-NNN`: предусловие/результат, существующие понятия и действия, кандидат на покрывающее требование, недостающие определения и открытые вопросы.
3. Предложи минимальный набор `REQ`, который покрывает подтверждённые намерения без дублирования. Для каждого укажи черновое имя, `type` (`structural`, `predicative`, `negative`), `dom`, `covers` и аргументы, источники и критерий приёмки.
4. Для каждого кандидата `REQ` укажи, какие независимо проверяемые утверждения могут стать отдельными `CON` в `design/floor2/constraints/CON-NNN.yaml`, а какие пока остаются полуформальными. Не называй `CON` синонимом любого требования: это запись с сигнатурой и предикатом.
5. Отметь необходимые диаграммы: `COMM` → `design/floor2/diagrams/comm/`; `STR` → `design/floor2/diagrams/string/`. У каждого предложения поясни, какой вопрос диаграмма делает проверяемым. Если текстового контракта достаточно, диаграмму не предлагай.
6. Найди пробелы, потенциальные противоречия и вопросы, где требуется решение человека. Различай блокирующие решения и вопросы, которые можно безопасно оставить `unresolved` в `draft`.
7. Не придумывай не заданные значения, поведение, числовые пороги и технические возможности. Не считай отсутствие данных подтверждением отсутствия ограничения.

## Формат ответа

A. Краткая оценка готовности этажа 1.

B. Матрица покрытия `US → candidate REQ → candidate CON/diagram`.

C. Предложенный список файлов с точными путями и коротким содержанием:
- `design/floor2/requirements/REQ-NNN.yaml`
- `design/floor2/constraints/CON-NNN.yaml`
- `design/floor2/diagrams/comm/COMM-NNN.yaml`
- `design/floor2/diagrams/string/STR-NNN.yaml`

D. Открытые вопросы, сгруппированные на блокирующие и неблокирующие.

E. Решения/конфликты, которые следует записать в `design/trace/nav-log.yaml`.

F. Явный список недостающих входных файлов и непроведённых проверок.

Остановись после плана и дождись, пока пользователь одобрит его или ответит на блокирующие вопросы. Для создания файлов затем используй `design_docs/prompts/p-create-requirement.md`.
