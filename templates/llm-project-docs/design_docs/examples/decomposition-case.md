# Учебный пример декомпозиции

> Это иллюстрация метода, не утверждение о конкретном проекте.

## Верхний контракт

«Приложение загружает валидную конфигурацию при старте и применяет параметры; при неверной конфигурации старт завершается понятной диагностикой, а не частичным состоянием».

## Предлагаемый базис

1. `config_reader`: чтение байтов и обработка ошибок файловой системы.
2. `config_parser`: преобразование байтов в типизированное представление.
3. `config_validator`: проверка схемы и взаимных ограничений параметров.
4. `config_applier`: перенос валидных значений в состояние приложения.

Базис проверяется сборкой, типами, unit-тестами для каждого шага и интеграционными тестами всей цепочки. Сам факт наличия четырёх компонентов не доказывает полноту разбиения.

## Границы и глобальные условия

- **Local:** parser должен возвращать типизированное представление либо ошибку разбора.
- **Boundary:** validator получает именно версию AST/структуры, которую выдаёт parser; ошибки не теряются при передаче.
- **Global:** при любой ошибке приложение не должно применять частично валидированные настройки; сообщения об ошибке должны указывать причину/путь.

## Возможный остаток

Если тест показывает, что часть параметров применяется до завершения валидации, это сигнал пропущенного граничного/глобального условия. Нужно проверить трассу состояния и контракты; не считать сам тест автоматически доказательством неудачного базиса.

## Проверка сохранения

Проверь: валидная конфигурация применяется; неверная конфигурация отклоняется; ошибки чтения/разбора/валидации различимы; состояние не изменяется частично; внешний контракт и сообщения о сбое сохраняются.
